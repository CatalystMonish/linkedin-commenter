# LinkedIn Comment Tracker

Chrome extension (MV3) that counts the comments you post on LinkedIn and shows
**Today / This Week / This Month** in a floating card on the page and in the
toolbar popup. Everything stays on your device — no account, no server, no
network calls of its own.

## Install (unpacked)

1. `chrome://extensions` → enable **Developer mode**.
2. **Load unpacked** → pick this folder.
3. Open `https://www.linkedin.com/feed/` and reload the tab.

The card sits bottom-right. Drag it by its header to move it, click the header
to collapse it, hide it entirely from the popup.

## How counting works

A content script running in the page's MAIN world wraps `fetch` and
`XMLHttpRequest`. When LinkedIn sends a **successful POST** that creates a
comment (`/voyager/api/...normComments`, or the graphql equivalent), the page
posts a message containing only a random id and `comment`/`reply` — never the
comment text. The service worker de-duplicates on that id and increments today's
counter in `chrome.storage.local`.

Deliberately not counted: failed sends, edits (a comment URN in the path, or a
`patch` body), deletes, reactions, follows, post/share creation (which also
carries a `commentary` field), and every other request through the shared
`/graphql` endpoint.

If LinkedIn's request shape changes enough that nothing matches, a DOM fallback
takes over: it watches for the comment editor being submitted (the submit button
or Enter with text in the box). The worker ignores fallback events the moment
network detection fires even once, so the two can never both count the same
comment. The popup shows which one is live.

Counts are stored per local day (`YYYY-MM-DD`). Week and month totals are summed
from those day buckets at read time, so nothing has to reset at midnight and the
week start (Mon/Sun) can be changed retroactively.

## Limits

- **No backfill.** Counting starts when you install it; LinkedIn exposes no
  comment history to read from. Use the popup's `+ / −` to seed today by hand.
- **Per browser profile.** Data lives in `chrome.storage.local`, so a second
  computer keeps its own counts.
- Day buckets older than 400 days are dropped.
- Replies to comments count toward the total (also tracked separately in storage).

## Layout

```
manifest.json
src/
  interceptor.js          MAIN world — patches fetch/XHR, emits an event
  bridge.js               isolated world — validates and relays to the worker
  widget/widget.js        floating card (shadow DOM, draggable, collapsible)
  background/service-worker.js   dedupe, count, badge, broadcast
  lib/constants.js dates.js storage.js    shared, plain scripts on globalThis.LCT
  popup/                  popup.html/js/css
icons/                    generated by test/mkicons.py
test/                     node-only tests, no dependencies
```

No build step and no bundler: the libs are plain scripts, the service worker is
a classic worker that `importScripts()` them, and the popup loads them with
`<script>` tags.

## Tests

```
node test/run.mjs
```

Covers the date maths (week/month boundaries, DST, rollover), the storage layer
(dedupe, concurrent increments, adjust floor, pruning, junk-state recovery) and
the interceptor's classification — creates and replies count; edits, deletes,
reactions, feed fetches and failed requests do not.

These run against *expected* LinkedIn payload shapes. Confirm the real ones once
after install (see below); if LinkedIn changes its API, the patterns in
`src/interceptor.js` are the only thing to update.

## Debugging

Turn on **Debug logging** in the popup (or run `localStorage.LCT_DEBUG = '1'` on
linkedin.com), reload, and every POST to the voyager API logs to the page console
with the match decision:

```
[LCT] POST 201 /voyager/api/socialDash/normComments MATCH comment
[LCT] POST 200 /voyager/api/graphql skip: graphql, not a comment operation
```

With debug on, *every* POST is logged, not just ones on a comment-looking URL —
so an endpoint we don't recognise still shows up with its payload. The fallback
logs under `[LCT dom]`.

Filter the console on `[LCT]`. Post one comment and confirm exactly one `MATCH`.
Then like a post, react to a comment, follow someone and edit an old comment —
none of those may produce a `MATCH`.

The popup's **Diagnostics** panel says the same thing without a console: which
detectors loaded, how many candidate POSTs were inspected, whether network
detection has ever matched, when the editor was last submitted, and the reason
each recent request was rejected. **Copy** puts it on the clipboard.

Storage and worker logs: `chrome://extensions` → the extension's **service
worker** link.
